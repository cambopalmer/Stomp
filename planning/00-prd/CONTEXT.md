# Stage 00: PRD (Product Requirements Document)

## Inputs
- `../IDENTITY.md` — what STOMP is / is not
- `../CONTEXT.md` — confirmed decisions
- `../_config/glossary.md` — shared vocabulary
- user answers to open questions A1–A9 (2026-08-31)

## Process
1. Summary + problem statement.
2. Goals (measurable) and non-goals / out of scope.
3. Personas.
4. User stories per section.
5. Functional requirements (tagged by phase) + non-functional requirements.
6. Success criteria, metrics, milestones.
7. Risks, open issues.

## Outputs
- `output/prd.md` — standard PRD format.

## Review gate
User confirms goals, non-goals, and the Phase 0 functional-requirement set (FR-1…FR-7) before architecture/schema are frozen.
